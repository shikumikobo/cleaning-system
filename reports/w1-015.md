## AI が決めた点（箱に「確認」で）

詳細は design.md の6章。主なもの：

1. 受け取りの初めの値は、人ごとの行を作らず種類の `default_push`・`default_email`（通知は入、メールは切。見積の承認・入金の遅れだけメールも入）
2. 一覧の行（`channel = app`）は設定にかかわらず常に作り、手段（通知・メール）は設定で切れる
3. 有効な端末がなければ通知の行は作らない。種類に要る権限（`amount.read`）を持たない人には作らない（スタッフに見積の知らせが出ない）
4. 二重の実行は、`job_runs` の部分一意の索引（会社・種類ごとに `running` は1つ）で止める。30 分を過ぎた `running` は失敗で閉じる
5. 端末の登録は RPC だけ（直接 insert させない）。1台を2人が使うとき、前の人の登録を消す
6. `work.assign` や管理者にも他人のお知らせ・設定は読ませない（`supervise_perm: none`）
7. 送る行は会社ごとに 100 行まで／回（1 分ごとに回す前提）

## メールの送信サービスの候補（登録・契約はしていない。人が決める）

- Resend：設定が簡単で、無料枠がある。HTTP の API で、1 ファイルで足せる
- Amazon SES（東京）：1 通あたりが最も安い。独自ドメインの認証（SPF・DKIM）と、送信の上限の引き上げ申請が要る
- SendGrid：実績が多いが、無料枠の条件が変わりやすい

推奨：試用の間は Resend（登録は人。ドメインの認証だけ要る）。会社が増えたら SES。決まったら `_shared/adapters.ts` の `mailProviders` に1つ足し、`MAIL_PROVIDER` を設定する。
