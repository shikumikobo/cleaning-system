## 再開の手順

1. `git -C ../cleaning-wt/<ブランチ> status` で作りかけを確かめる。コミット済みなら取り込みへ、作りかけなら同じブランチでサブの作業を再開する（依頼の文は、セッションの一時フォルダの `brief-<ブランチ>.md`。消えていたら `specs/product.md`・`crud.md` の機能の節と、この表から作り直す）
2. 共通の決まり：DB のテストは Docker だけ（`$env:CONTAINER="pg-<ブランチ>"; node tools/docker/run.mjs`）。開発は Sonnet、簡単なテストは Haiku
3. 波の全部の機能を main に取り込み、つなぎを直し、全部の検査（Docker・`pnpm -r test`・lint・typecheck・build・`apps/web` で `test:e2e`・`spec.py check --strict`）を通す
4. 波が終わったら push：`git push origin main:refs/heads/cleaning/main`（shikumikobo/job の別ブランチ）
5. 承認待ちの箱に波の確認を入れる（B-037 以降。波3・4 はまだ入れていない）
6. 波0〜6 は完了。残りは 007 課金（人の決定 3-52 待ち）、承認待ちの箱への波3〜6の確認、e2e の不安定なテスト（下）
