# 機能008：現場の写真（設計）

要件は [requirements.md](requirements.md)。表と policy の型は [../data-model.md](../data-model.md)（008 の章）が正で、ここは 008 での実際の形を書く。

## 1. 表：`photos`

共通の列（`id`・`tenant_id`・作成と更新の人と時刻・`deleted_at`）と `unique (tenant_id, id)` は data-model.md のとおり。

| 列 | 中身 | 制約 |
|---|---|---|
| `id` | 端末で作った uuid をそのまま使う（二度送っても 1 件） | 主キー |
| `building_id` | 建物 | 必須。`(tenant_id, building_id)` の組の外部キー |
| `area_id`・`room_id` | 場所・部屋 | 任意。組の外部キー |
| `work_id` | 作業（010） | 任意。`(tenant_id, work_id)` の組の外部キー（波 3 の取り込み、`20261120010000`） |
| `report_item_id` | 報告書の項目（009） | 任意。**列と索引だけ**（009 を取り込むとき足す） |
| `request_id` | 案件（003） | 任意。組の外部キー。入れるのは RPC だけ |
| `kind` | 前 `before`・後 `after`・気づき `observation` | check |
| `taken_at`・`taken_by` | 端末で撮った時刻・撮った人（所属） | 必須 |
| `storage_path`・`thumb_path` | 置き場所 | `<tenant_id>/photos/<id>/photo.jpg`・`thumb.jpg` と一致（check） |
| `width`・`height`・`bytes` | 寸法と大きさ | 0 より大きい |

索引：建物・日、案件・作業・報告書の項目（null でないもの）、撮った人。

## 2. 権限

`apply_policy('public.photos', 'C2', …)`（型 C2＋D）。

- 持ち主の判定 `app.is_my_photo(tenant, 行)`：社内の人で、作業つきなら「その作業の担当」、作業なしなら「撮った本人」。作業の担当は、010 の本物の `work_assignments`（消していない行）を直接読む（波 3 の取り込みで、表の有無を見る分岐をなくした）。担当が 1 人もいない作業の写真は、撮った本人でも読めず、`work.assign` を持つ人だけが読める
- 読む：持ち主と `work.assign`。直す・消す：持ち主で、報告書が下書きの間（`app.photo_report_locked`。009 が本物に置き換える。それまでは常に false）
- 作る：`field.record` で、撮った人は自分（案件のつなぎは自分が読める案件だけ）
- 外部の人：`app.photo_external_visible`（009 が本物に置き換える。今は常に false）が真の行だけ
- 直せる列は、種類・場所・部屋・消す（`deleted_at`）だけに絞る。案件のつなぎは RPC だけ
- 建物を消すとき：`app.usage_refs` に `building → cascade → photos` を足す。部屋・場所は 002 の既存の行（photos を使う → 消さず「使わない」）

## 3. 置き場所・期限つき URL・掃除

- 置き場所は 005 の非公開の `tenant-files` の `<tenant_id>/photos/<写真の id>/`
- `sign-file-urls`（005）に、任意の `source`（`files`＝既定・`photos`）と `variant`（`original`＝既定・`thumb`）を足した最小の変更。呼んだ人のログインの鍵で `photos` を読み（RLS が見える行を決める）、`thumb` なら `thumb_path` を署名する。一覧は小さな画像だけを署名する
- 掃除：005 の `sweep-files` の会社ごとの 1 回の中で、ファイルの掃除のあとに、DB の関数 `photo_sweep_orphans`・`photo_sweep_rows`（service_role だけ）を呼ぶ。対象は `<tenant>/photos/` の下だけ。記録は 005 の `job_runs`（件数に `photos_removed`・`photo_rows_deleted` を足す）

## 4. 気づきから案件

003 の `create_request_from_observation` に `p_photo_ids uuid[] default null` を足して作り直す（旧い 6 引数の関数は消し、1 つだけにする）。同じ会社・同じ建物・気づき・まだ案件に付いていない・呼んだ人が直せる・報告書が固定されていない写真だけをつなぎ、1 つでも合わなければ案件ごと戻す。二度目の呼び出しは前の結果を返し、写真に触らない。

## 5. 端末（PWA）

- `<input type="file" accept="image/*" capture="environment">` でカメラを開く
- 端末で縮小（canvas で描き直す＝Exif は入らない）→ 付属の情報が残っていないことを確かめる → 元の画像（長辺 1600px・品質 0.8）と小さな画像（長辺 320px・品質 0.7）
- 端末の入れ物（IndexedDB。波 0 の `lib/offline/db`）にためる → 電波が戻ったら、元の画像 → 小さな画像 → 行（既にあれば無視する書き方）の順に送る。画像が上がらなければ行は作らない
- 断られた写真は理由つきで端末に残し、人があきらめて消せる
- 気づきを案件にもするときは、案件の uuid を先に作り、案件の気づき → 写真の順に送る

## 6. 画面

撮る（`/photos/new/`）、一覧（`/photos/`。日本時間の日ごと・建物・日・種類で絞る・小さな画像だけ）、詳細（`/photos/detail/`。元の画像・直す・消す・案件へ）、気づきから案件（`/photos/request/`）。ホームに 1 行のリンク。

## 7. 決めたこと

- **縮小の幅**：元の画像は長辺 1600px（JPEG 品質 0.8）、小さな画像は長辺 320px（品質 0.7）。理由：報告書で十分読める細かさと、回線の細い現場での送りやすさの釣り合い。値は定数 1 か所で変えられる
- **残す期間**：写真は期間では自動で消さない。人が消した写真（論理削除）と、行のない実体は、掃除が猶予（1 日）のあとに消す。理由：写真は報告書の証拠で、期間の上限を先に決めると必要な写真を失う。長期の整理は、容量が問題になったときに期間つきの掃除を足す（退会した会社の消去は 007）
- **作業の担当の判定**：010 の本物の表で、作業つきは担当の全員、作業なしは撮った本人。取り込みの前は「表がない間は撮った本人」としていたが、表ができた今は R-008-8（持ち主は作業の担当。担当でない人は、自分が撮っていても読めない）がそのまま効くので、その分岐とテストは外した。外された担当（`deleted_at` あり）は担当に数えない（008 では見落としていたので、取り込みで直した）。担当が 0 人の作業は、撮った本人に戻さず R-008-8 のとおり `work.assign` の人だけが読める（推奨の案）
- **外部の人**：提出済みの報告書の写真だけ、という条件は報告書（009）が要る。今は読めない形（`photo_external_visible` が false）にし、009 が関数を置き換える
- **写真の読み出しの署名**：専用の関数は作らず、005 の `sign-file-urls` に引数を足した（最小の変更）
- **日の区切り**：画面の「日」は日本時間（0 時〜翌 0 時）
