# 機能008：現場の写真（要件）

状態：実装
作成：2026-11-17

全体の言葉と役割は [../product.md](../product.md)、変えない決まりは [../constitution.md](../constitution.md)、表と policy の型は [../data-model.md](../data-model.md)（008 の章）、CRUD は [../crud.md](../crud.md)（008 の章）。置き場所と期限つき URL・掃除は [../005-files-portal/design.md](../005-files-portal/design.md)、気づきから案件を作る RPC は [../003-requests/design.md](../003-requests/design.md)。

## 1. ねらい

現場のスタッフが、スマホで、作業の前・後と気づきの写真を撮り、建物・場所・部屋とひもづけて残す。電波がなくても撮れて、戻ったら送られる。気づきの写真からは、そのまま案件を作れる。報告書（009）・作業（010）は並列・後で作るので、それらへのつなぎは列と索引だけ置く。

## 2. 利用者の話

- スタッフとして、現場でスマホのカメラで撮り、種類（前・後・気づき）と場所を付けて残したい。電波がなくても失いたくない
- スタッフとして、気づき（破損・汚れなど）の写真を選んで、そのまま案件にしたい
- 社員として、建物・日・作業・案件ごとに写真を見たい。一覧は軽くあってほしい
- 撮った本人として、種類と場所を直し、間違えた写真を消したい（報告書が下書きの間だけ）
- 外部の人には、提出した報告書の写真だけを見せたい（報告書は 009。今は見せない）

## 3. 受け入れ基準

### 写真の行

- **R-008-1** `field.record` を持つ人（スタッフ・社員・管理者）が、自分が撮った写真の行（建物・種類・撮った時刻・置き場所・幅・高さ・大きさ）を作ったとき、システムはそれを保存する
- **R-008-2** 種類が前・後・気づき以外、置き場所が `<tenant_id>/photos/<写真の id>/photo.jpg`（小さな画像は `thumb.jpg`）でない、幅・高さ・大きさが 0 以下ならば、システムはその行を保存しない
- **R-008-3** 別の会社の建物・部屋・場所・案件を指すならば、システムはその行を保存しない
- **R-008-4** 部屋・場所・案件・作業・報告書の項目は、付けても付けなくても保存する。作業・報告書の項目は、相手の表ができるまで列と索引だけで、外部キーは付けない
- **R-008-5** 同じ uuid の写真は 1 件だけ。端末の送り直し（既にあれば無視する書き方）は、二度送っても増えない
- **R-008-6** 撮った本人は、種類・場所・部屋を直せる（空にもできる）。建物・撮った人・撮った時刻・置き場所・案件のつなぎは直せない

### 権限

- **R-008-7** 作業のない写真は、撮った本人だけが読み、直し、消せる。同じ会社のほかのスタッフには見えない。`work.assign` を持つ人は読める
- **R-008-8** 作業のある写真は、その作業の担当の全員が読み・直せる（作業と担当の表（010）ができたあと。それまでは撮った本人で決める）。担当でない人は、自分が撮っていても作業の写真は読めない
- **R-008-9** 報告書が下書きの間だけ、写真を直せ・消せる。提出・確認のあとは、直せず・消せない（報告書の表（009）ができるまでは、固定される写真はない）
- **R-008-10** 外部の人は、写真を作れず・直せず・消せない。外部の人が読めるのは、提出した報告書の写真だけ（009 が足す。それまでは何も読めない）
- **R-008-11** 別の会社の写真は、読めず・書けず・数も分からない
- **R-008-12** 部屋・場所が写真から使われているときは、消さずに「使わない」にする。建物を消すときは、その建物の写真の行も論理削除する（実体は掃除が消す）

### 気づきから案件

- **R-008-13** 気づきの写真を付けて案件を作ったとき（`create_request_from_observation` の `p_photo_ids`）、システムは案件を作り、写真の `request_id` に案件の ID を入れる
- **R-008-14** 気づきでない写真・案件と別の建物の写真・すでに案件に付いた写真は、つなげられず（22023）、見えない・直せない・報告書が固定された写真は 42501 で断り、案件も作らず全部を戻す
- **R-008-15** 同じ案件の uuid で二度呼んでも案件は 1 件。二度目は写真に触らない

### 掃除

- **R-008-16** 行のない写真の実体（`<tenant>/photos/` の下。猶予より前に作られたもの）を、定時の処理が消す。行のある写真（元の画像・小さな画像とも）・作ったばかりのものは消さない
- **R-008-17** 猶予より前の、実体のない写真の行を論理削除する。実体のある行は消さない
- **R-008-18** 掃除の関数を呼べるのは service_role だけ。管理者・スタッフ・ログインしていない人は呼べない
- **R-008-19** 写真の掃除は、ファイルの掃除（005）のあと、同じ会社の同じ記録の中で行う。`photos/` の外・別の会社のパスは消さない。失敗した会社は失敗で記録を閉じ、ほかの会社を続ける

### 期限つきの URL

- **R-008-20** `sign-file-urls` に `source: "photos"`・`variant: "thumb"`（省くと元の画像）を渡すと、見える写真の URL を 1 回の署名でまとめて返す。見えない写真（別の会社・外部の人に見せない・消した）は区別せず「見つからない」。`source` を省くと、これまでどおりファイル（005）
- **R-008-21** `source`・`variant` が決まった値でなければ、何も読まず・作らず、400 で断る

### 撮る（端末）

- **R-008-22** 端末で、長辺が上限（元の画像 1600px、小さな画像 320px）を超えるときだけ縮め、縦横比を保つ。小さい画像は拡大しない
- **R-008-23** 送る前に、JPEG の Exif（位置）・ICC・コメントなどの付属の情報を消す。JPEG でない・壊れたものは、そのまま送らず断る
- **R-008-24** 撮ったら、まず端末にためる（元の画像・小さな画像・行の中身）。電波がない間は送らず残し、戻ったら元の画像 → 小さな画像 → 行の順に送って端末から消す。画像が上がらなければ行は作らない
- **R-008-25** 同じ uuid は、ためるのも 1 件（先にためた中身を残す）。届いていた（重複）も送れたこととして消す。送りの途中でつながらなくなったら止め、続きから送る。同時に 2 回呼んでも二重に送らない
- **R-008-26** サーバーに断られた写真は、端末に残し（理由を覚え）、次の写真を送る。ログインが切れていたら止める。送れない写真は、人が選んで、あきらめて端末から消せる
- **R-008-27** 気づきの写真に案件の uuid を付けておくと、行の `request_id` に入る（案件を作る気づきを先に送ってから送る）
- **R-008-28** 置き場所の組み立ては、DB の check と同じ（`<会社>/photos/<写真の id>/photo.jpg`・`thumb.jpg`）
- **R-008-31** 撮る前の検査：建物が要る。種類は前・後・気づき。気づきから案件を作るなら題名が要る。建物を選んでいなければ撮っても送らず理由を出す。カメラの入力は端末のカメラを開く形（capture）

### 一覧・詳細・直す（画面）

- **R-008-29** 一覧は新しい順に、日本時間の日ごとにまとめ、建物・日・案件・作業・種類で絞れる（消した写真は出さない）
- **R-008-30** 日の範囲は、日本時間の 0 時から翌日の 0 時（UTC では前日の 15 時から）
- **R-008-32** 一覧は小さな画像の URL だけを取る（元の画像は取らない）。ホームに「現場の写真」のリンクがある
- **R-008-33** 詳細は、元の画像を期限つきの URL で出し、撮った日時（日本時間）・建物・場所・部屋・案件へのリンクを出す
- **R-008-34** 撮った本人は、種類と場所を直して保存でき、消せる（論理削除）
- **R-008-35** 直す・消すを出すのは撮った本人だけ（判定は DB。画面は出し分け）。読むだけの人には出さない
- **R-008-36** 気づきの写真を選んで題名を入れると、003 の RPC に写真の ID を渡し、案件の画面へ移る。案件に付いた写真は候補に出ない。写真を選ばない・題名がないときは送らず理由を出す。詳細の「この気づきを案件にする」から、その写真を選んだ状態で開ける
- **R-008-37** 電波がないときは端末にため、ためた件数を出す。戻ったら自動で送る。送れていない写真は理由つきで残し、あきらめて消せる

## 4. この機能に含めないこと

- 報告書・作業の表と、それらへの外部キー（009・010）。外部の人が提出済みの報告書の写真を読む policy の本物（009）
- 写真の自動の分類・加工・文字入れ

## 5. 人の確認が要ること

- 写真を残す期間（design.md の「決めたこと」の推奨でよいか）
