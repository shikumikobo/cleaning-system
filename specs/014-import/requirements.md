# 機能014：データの取り込み（要件）

状態：実装
作成：2026-11-20

全体の言葉と役割は [../product.md](../product.md)、変えない決まりは [../constitution.md](../constitution.md)、表と policy の型は [../data-model.md](../data-model.md)（013・014 の章）、CRUD は [../crud.md](../crud.md)（014 の章。課題4）。001（権限・履歴）・002（取引先・建物・部屋）・010（契約。`create_contract_import`）が前提。

## 1. ねらい

これまで紙・Excel で管理してきた取引先・建物・部屋・清掃の契約を、Excel（.xlsx）か CSV から一度に登録する。いきなり書かず、ファイルを選ぶと「取り込む前の確かめ」（取り込める件数・同じものの重なり・エラーの行）が出て、人が OK を押したときだけ書く。書くときは、取り込んだ人のログインの鍵で RPC を呼ぶ（RLS と権限を通る。`service_role` は使わない）。

## 2. 利用者の話

- 社員として、取引先の一覧を Excel のまま取り込みたい。ひな形をダウンロードして、見出しに合わせて貼りたい
- 取り込む前に、間違いのある行と、すでに登録済みのものとの重なりを知りたい。間違いのない行だけ取り込みたい
- 取り込んだあと、いくつ登録され、いくつ飛ばし、どの行がだめだったかを見たい
- 管理者として、いつ・だれが・何を取り込んだかを残したい（履歴）
- スタッフ・外部の人は取り込めない。別の会社のデータは見えず、取り込めない

## 3. 受け入れ基準

### ひな形

- **R-014-1** 取引先・建物・部屋・契約のそれぞれについて、CSV と Excel（.xlsx）のひな形をダウンロードできる。見出しは日本語で、入れ方の例の行がつく。ひな形をそのまま読み戻すと、例の行が誤りなく読める（取引先 → 建物 → 部屋 → 契約の順に取り込む）

### ファイルの読み込み

- **R-014-2** CSV は UTF-8（BOM の有無を問わない）と Shift_JIS（Excel の「CSV」の保存）を読める。引用符・セルの中のカンマ・改行・CRLF・末尾の空行を正しく扱う
- **R-014-3** .xlsx は、取り込む種類の名前（取引先・建物・部屋・契約）のシートがあればそれを、なければ最初のシートを読む。数値・日付・時刻のセルも、画面に見えるとおりの文字にして読む
- **R-014-4** 見出しの順番は問わない（見出しの名前で探す。全角半角・空白の違いは無視）。必須の見出しが足りなければ、ファイル全体のエラーにして、足りない見出しの名前を出す。知らない見出しは無視し、そのことを知らせる。空の行は飛ばし、行番号はファイルの行のとおり（見出しが1行目）に出す

### 確かめ（検査）

- **R-014-5** 取引先の行：名前が必須、種類（管理会社・オーナー。`management_company`・`owner` も可。空は管理会社）、メールの形、締め日は 1〜31 の整数（31 は月末。「月末」と書いても 31）。正しくない行は、行番号・項目・理由を出し、取り込まない
- **R-014-6** 建物の行：取引先名（登録済みで1つに決まること）・建物名・住所が必須。所有者名（任意）は、あれば登録済みで1つに決まること。同じ名前の取引先が2つあって決まらないときもエラー
- **R-014-7** 部屋の行：取引先名・建物名（登録済みで1つに決まること）・部屋番号が必須。階は整数（任意）
- **R-014-8** 契約の行（1行が清掃の中身1つ）：取引先名・建物名（登録済みで1つに決まること）、契約の種類（定期・単発）、開始日、終了日（開始日以後）、清掃の名前、清掃の種類（基本・オプション・特別清掃）、金額（0 以上の整数）、請求の仕方（毎月・行った回ごと。空は種類に応じて）、頻度（RRULE か「毎週月曜」「隔週火曜」「毎月第2水曜」「毎月15日」「毎月末」「3か月に1回」「単発」。空は単発）、開始時刻・終了時刻（終了が後）。取引先・建物・種類・開始日・終了日が同じ行は、1つの契約の中身としてまとめる。まとめた中の1行でも正しくなければ、その契約は全部取り込まない
- **R-014-9** 同じものの重なり：ファイルの中で2回目以降のもの、すでに登録されているものと同じものは「重なり」とし、エラーとは別に数え、取り込まない（飛ばす）。同じかどうかは、全角半角・空白・英字の大文字小文字の違いを無視して比べる。取引先は名前、建物は取引先と名前、部屋は建物と部屋番号、契約は建物・種類・開始日・清掃の名前の組

### 確かめの画面と取り込み

- **R-014-10** ファイルを選ぶと、確かめの画面に、取り込める件数・重なりの件数・エラーの行の件数と、エラーの行の一覧（行番号・項目・理由）・重なりの一覧が出る。この時点では、何も書かない（取り込みの RPC を呼ばない）
- **R-014-11** 「この内容で取り込む」を押したときだけ、取り込める行を RPC で書く。エラーと重なりの行は書かない。取り込める行が0なら押せない。ファイルを選び直すと、確かめからやり直す
- **R-014-12** 取り込みは、取り込んだ人のログインの鍵で RPC `import_rows` を呼ぶ（`service_role` を使わない）。RPC は `master.edit`（契約は `contract.edit` も）を確かめ、権限のない人（スタッフ・外部の人・運営・どこにも属さない人・ログインしていない人）・別の会社を指す呼びは、権限がないのと同じ扱いで断る
- **R-014-13** 書く内容は、サーバーでも検査と重なりの確かめをやり直す。画面の確かめを通らない呼びでも、正しくない行・重なりの行は書かず、結果に理由を返す。会社は呼ぶ人の会社で、名前は同じ会社の登録済みのものだけで探す（別の会社の取引先・建物は見つからない扱い）
- **R-014-14** 契約は、010 の `create_contract_import` を呼んで作る（見積なし・元は取り込み・中身も同時）。中身が1つでも正しくなければ、その契約は半分も作らない
- **R-014-15** 取り込みを、1つの記録 `import_jobs` に残す（種類・ファイル名・状況・行の数・取り込んだ数・重なりの数・エラーの数・エラーと重なりの行の一覧）。読めるのは `master.edit` を持つ人だけで、画面や API から直接書けない（RPC だけ）。別の会社の記録は読めない
- **R-014-16** 取り込んで作った取引先・建物・部屋の履歴（`audit_logs`）の source は「取り込み」（import）になる。作った人（取引先・建物・部屋・契約）は取り込んだ人になる（契約の履歴の source は、010 の RPC が決める）

### 画面

- **R-014-17** 取り込みの結果の画面に、取り込んだ件数・重なりで飛ばした件数・エラーの件数と、エラーの行の一覧が出る。RPC が断った理由は日本語で出す
- **R-014-18** `master.edit` を持たない人には、ファイルを上げる操作を出さない。契約は `contract.edit` を持たない人には選べない（出し分けのためだけ。判定は DB が行う）
- **R-014-19** 取り込みの履歴（日時・種類・ファイル名・件数）を一覧で見られる
