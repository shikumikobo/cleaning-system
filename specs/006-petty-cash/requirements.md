# 機能006：小口現金・レシート（要件）

状態：実装
作成：2026-11-16

全体の言葉と役割は [../product.md](../product.md)、変えない決まりは [../constitution.md](../constitution.md)、表と policy の型は [../data-model.md](../data-model.md)（006 の表、型 C1）、CRUD は [../crud.md](../crud.md)。001（会社・利用者・権限）が前提。

## 1. ねらい

スタッフに渡した小口現金の出入りと、使ったときのレシートを、手作業ではなくシステムで整理する。スタッフはスマホで、出金とレシートの写真をその場で登録する（電波がなくても端末にためる）。管理者・社員は、全員の出納を確認し、月を締め、会計ソフトに渡す CSV を出す。確認したあとの数字は、だれも直せない。

## 2. 利用者の話

- スタッフとして、買い物のあとすぐ、金額・用途・レシートの写真を登録したい。事務所に戻ってから書き直さなくて済むように
- スタッフとして、自分の小口の残高と、自分の出入りだけを見たい
- 管理者・社員として、スタッフに現金を渡した記録（入金）を付けたい
- 管理者・社員として、全員の出入りとレシートを見比べて確認したい
- 管理者・社員として、月の終わりに、確認した分を締めて、あとから数字が変わらないようにしたい
- 管理者・社員として、会計ソフトに渡す CSV を出したい

## 3. 受け入れ基準

### 小口（持ち手ごとの現金の入れ物）

- **R-006-1** `cash.manage` を持つ人が持ち手と名前を入れて小口を作ったとき、システムは小口を作る（持ち手は、その会社の所属）
- **R-006-2** `cash.manage` を持たない人ならば、システムは小口を作らせず、直させない（持ち手の本人も、外部の人も同じ）
- **R-006-3** 持ち手の本人のとき、システムは自分の小口を読ませる。持ち手でも `cash.manage` でもない人ならば、他人の小口を読ませない。`cash.manage` を持つ人には、会社の全員の小口を読ませる
- **R-006-4** システムは常に、小口の残高を、出入りの合計（入金 − 出金。消した行を除く）から出す。見る人の権限で見える行だけを数える
- **R-006-5** 残高が0でない小口ならば、システムは消させない（残高が0なら消せる）

### 出入りの登録（出納帳）

- **R-006-6** 持ち手の本人が日付・金額・用途を入れて出金を登録したとき、システムは「下書き」で保存する。金額は1円以上の整数、用途は空でない
- **R-006-7** `cash.manage` を持つ人が、持ち手に渡した現金（入金）を登録したとき、システムは「下書き」で保存する。持ち手の本人ならば、入金を登録させない
- **R-006-8** 自分の小口ではない出入りならば、システムは `cash.manage` を持たない人に登録させない（別の持ち手の小口、別の会社の小口も同じ）
- **R-006-9** 同じ端末の ID の出入りを二度送ったとき、システムは1件だけにする（二度目は何もしない）
- **R-006-10** 電波のない間に登録した出入りは、システムは端末にため、電波が戻ったら自動で送る。送れるまで端末から消さず、送れていない件数を画面に出す
- **R-006-11** 出入りが下書きの間、持ち手の本人と `cash.manage` を持つ人は、それを直せ、消せる（論理削除）
- **R-006-12** 出入りが確認済み・締め済みならば、システムは持ち手の本人にも `cash.manage` を持つ人にも、それを直させず、消させない
- **R-006-13** システムは、画面から出入りの status を直接書き換えさせない（確認・締めは RPC だけ）。下書き以外で出入りを作らせない
- **R-006-14** 持ち手の本人ならば、システムは他人の出入りを読ませない。`cash.manage` を持つ人には、会社の全員の出入りを読ませる

### 確認と月の締め

- **R-006-15** `cash.manage` を持つ人が出入りを確認したとき、システムはその下書きを「確認済み」にし、確認した人と時刻を残す
- **R-006-16** `cash.manage` を持たない人ならば、システムは確認も締めもさせない（持ち手の本人も）
- **R-006-17** すでに確認済みの出入りをもう一度確認しても、システムは何も変えず、エラーにしない
- **R-006-18** `cash.manage` を持つ人が月を締めたとき、システムはその月の確認済みの出入りを「締め済み」にし、締めた人と時刻を残す
- **R-006-19** その月に下書きが残っているならば、システムは月を締めない。まだ来ていない月も締めない
- **R-006-20** 締めた月の日付ならば、システムは出入りを新しく作らせず、日付を動かして入れることもさせない
- **R-006-21** 別の会社の出入りならば、システムは確認も締めもさせない（RPC の呼び出しも）

### レシート

- **R-006-22** 持ち手の本人がレシートの画像を置いたとき、システムは `<会社の ID>/receipts/<レシートの ID>.<拡張子>` の置き場所の画像と、読み取り待ちの行を作る
- **R-006-23** 画像のパスが、自分の会社と自分のレシートの ID で始まらないならば、システムはレシートの行を作らせない
- **R-006-24** 画像から金額と日付が読み取れたとき、システムはそれをレシートに保存し「読み取り済み」にする。読み取れなかったときは「読み取れず」にして、手で入れる画面に進める
- **R-006-25** システムは、読み取った金額を、出入りの金額に勝手に入れない。持ち手が画面で確かめた金額だけを出入りに入れる（読み取りは候補）
- **R-006-26** システムは、読み取りの中身（どの読み取りの方法を使うか）を、Edge Function の中で差し替えられる形にする。決まった外部の有料のサービスには、つなげない
- **R-006-27** 確認済み・締め済みの出入りから使われているレシートならば、システムは持ち手の本人にもそれを直させず、消させない
- **R-006-28** 持ち手の本人ならば、システムは他人のレシートを読ませない。`cash.manage` を持つ人には、会社の全員のレシートを読ませる
- **R-006-29** 出入りに付けるレシートは、同じ持ち手のものだけ。システムは、別の持ち手や別の会社のレシートを付けさせない

### 会計ソフトに渡す CSV

- **R-006-30** `cash.manage` を持つ人が月と小口を選んだとき、システムは、その範囲の確認済み・締め済みの出入りを、会計ソフトに渡す CSV にする。下書きは含めない
- **R-006-31** CSV は、システムは常に UTF-8（先頭に BOM）・改行 CRLF・値は必要なときに引用符で囲む形で作る。金額は円の整数、日付は `YYYY/MM/DD`
- **R-006-32** CSV の値が `=`・`+`・`-`・`@` で始まるとき、システムは表計算ソフトが式として動かさないよう、先頭に `'` を付ける

### 守りと画面

- **R-006-33** 別の会社の行ならば、システムは 006 の3つの表で、読ませず、作らせず、直させず、消させない（数も分からない）。外部の人は、読ませず、書かせない
- **R-006-34** 出入りの入力で、金額が1円以上の整数でない・用途が空・日付がない・出金なのに小口がない、のとき、システムは画面で送る前に断る
- **R-006-35** 持ち手の画面で、システムは自分の小口の残高と、自分の出入り（下書き・確認済み・締め済みの別）と、送れていない件数を出す
- **R-006-36** 管理の画面で、システムは `cash.manage` を持つ人に、全員の出入りの一覧と、確認・月の締め・入金の登録・CSV の書き出しを出す。`cash.manage` を持たない人には、その操作を出さない（出さなくても、DB が拒否する）
- **R-006-37** `cash.manage` を持つ人のとき、システムは小口の持ち手の表示名（外部の人を除く、同じ会社の有効な所属）を返す。`cash.manage` を持たない人ならば、返さない

## 4. 範囲の外

- 建物・作業との紐づけの選択の画面（`building_id`・`work_id` は列だけ。002・012 ができたら足す）
- 費用としての粗利への集計（016）、決まった会計ソフトの専用の形式への書き出し（汎用の CSV まで）
- 読み取りの外部の有料のサービスへの接続。レシートの読み取りの中身は差し替えられる形までで、初めは「読み取らない（手で入れる）」
- 小口の締めの取り消し（締めたあとは直せない。直すときは、新しい月の出入りで調整する）

## 5. 決まっていないこと（推奨の案で進める）

| 点 | 推奨 | 理由 |
|---|---|---|
| 持ち手が登録できるもの | 出金だけ。入金（現金を渡した記録）は `cash.manage` が付ける | crud.md の006の行どおり。持ち手が自分で残高を増やせないように |
| 残高に入れる範囲 | 下書きも含める（現金は動いている）。確認済み以上だけの残高も別に出す | 持ち手には今の手持ちの額が要る。管理者には確認済みの額が要る |
| 残高がマイナスになるとき | 登録は止めず、画面に注意を出す | 立て替えは現場でよくある。止めると現場の記録が止まる |
| 月の締めの単位 | 会社全体、または小口ごと。月の1日から末日まで（日本時間） | 会計の月次に合わせる。小口ごとに締められると、持ち手ごとの遅れに対応できる |
| 読み取りの初期の方法 | 読み取らない。画像から値を取る処理は差し替えの口だけ作る | 外の有料のサービスを使うかは、費用を決めてから |
| CSV の列 | 下の design.md の3章 | 会計ソフトに渡す形は、取り込み設定で列を対応づけられるので、情報を落とさない形にする |
