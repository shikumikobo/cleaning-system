# 機能001：会社と利用者（要件）

状態：実装
作成：2026-11-16

全体の言葉と役割は [../product.md](../product.md)、変えない決まりは [../constitution.md](../constitution.md)、表と policy の型は [../data-model.md](../data-model.md)、CRUD は [../crud.md](../crud.md)。

## 1. ねらい

清掃会社が、自分の会社の人だけでシステムを使い始められるようにする。運営（しくみ工房）が会社を作り、その会社の管理者が社員・スタッフ・外部の人を招待する。どの会社のデータも、ほかの会社からは見えず、触れない。この機能で作る守りの仕組み（権限の判定・policy の型・変更の履歴・電波のない間の送り直し）は、後の全部の機能が使う。

## 2. 利用者の話

- 運営として、試用の会社を作り、その会社の最初の管理者を招待したい。試用を始めてもらうため
- 管理者として、社員・スタッフ・外部の人をメールで招待し、役割を決めたい。会社の人だけで使うため
- 管理者として、辞めた人をすぐ止めたい。止めた人にデータを見せないため
- 招待された人として、メールのリンクからログインの準備をして、すぐ使い始めたい
- 1人で2つの会社に入っている人として、会社を切り替えて使いたい
- 管理者として、だれがいつ何を変えたかを見たい。間違いを調べるため
- 運営として、問い合わせのとき、会社の管理者が許した期間だけ、データを見たい

## 3. 受け入れ基準

### 会社と運営

- **R-001-1** 運営が会社の名前と最初の管理者のメールアドレスを入れて会社を作ったとき、システムは試用の状況で会社を作り、その管理者への招待を送る
- **R-001-2** 運営ならば、システムは会社の業務のデータ（会社の情報と所属を除く）を、許された期間のほかは読ませない
- **R-001-3** 会社の管理者が運営の閲覧を期間つきで許したとき、システムはその期間だけ、運営にその会社のデータを読ませ、書かせない
- **R-001-4** 運営の閲覧の期間が過ぎるか、管理者が取り消したならば、システムはそのときから運営にその会社のデータを読ませない
- **R-001-5** 管理者が会社の情報（名前・住所・電話・インボイスの登録番号）を直したとき、システムはそれを保存する
- **R-001-6** 管理者でない人ならば、システムは会社の情報を直させない

### 招待とログイン

- **R-001-7** 管理者がメールアドレスと役割を入れて招待したとき、システムはその人に、7日間だけ使える招待のメールを送る
- **R-001-8** 招待された人がリンクを開いて表示名を入れたとき、システムはその人を、招待の役割で会社に所属させる
- **R-001-9** 期限の過ぎた招待、使い終わった招待、取り消した招待ならば、システムは所属させない
- **R-001-10** 招待のリンクの鍵は、システムは常にハッシュだけを持ち、もとの鍵を保存しない
- **R-001-11** 管理者が招待を取り消したとき、システムはその招待を使えなくする
- **R-001-12** 管理者でない人ならば、システムは招待をさせない
- **R-001-13** ログインはメールアドレスで行い、パスワードを使わない形（メールのリンク）を、システムは常に使う

### 所属と役割

- **R-001-14** 管理者が人の役割を変えたとき、システムは次の操作からその役割の権限で判定する
- **R-001-15** 管理者が人を止めたとき、システムはその人に、次の操作からその会社のデータを読ませず、書かせない
- **R-001-16** 会社に有効な管理者が1人だけのとき、システムはその人を止めたり管理者以外にしたりさせない
- **R-001-17** 1人が複数の会社に所属しているとき、システムは選んだ会社のデータだけを見せ、画面で会社を切り替えさせる
- **R-001-18** 管理者が外部の人に見られる建物を決めたとき、システムはその建物の分だけを外部の人に見せる（見せる中身は 002・004・005・009・012 で決める）

### 会社をまたがない守り（全部の表）

- **R-001-19** 別の会社の行ならば、システムはどの表でも、読ませず、作らせず、直させず、消させない（数も分からない）
- **R-001-20** 別の会社の親を指す子の行ならば、システムは作らせない
- **R-001-21** 置き場所のファイルのパスが自分の会社の ID で始まらないならば、システムは上げさせず、読ませない
- **R-001-22** システムは常に、すべての表で RLS を ON にし、どの表にも policy の型（A・B・C1・C2・D・E）のどれかを付ける
- **R-001-23** 権限を持たない操作ならば、システムは画面からも RPC からも行わせない

### 権限と役割の割り当て

- **R-001-24** システムは常に、役割ごとの権限を data-model.md の表のとおりに持つ（管理者は全部、社員は利用者の管理のほか全部、スタッフは現場の記録だけ、外部はなし）
- **R-001-25** スタッフと外部の人ならば、システムは型 B（金額）の表を読ませない

### 変更の履歴と処理の記録

- **R-001-26** 型 A・B・E の表の行を作る・直す・消すとき、システムはだれが・いつ・どこから・何を（変わった列の前と後）を履歴に残す
- **R-001-27** だれであっても、システムは変更の履歴を直させず、消させない
- **R-001-28** 管理者でない人ならば、システムは変更の履歴を読ませない
- **R-001-29** Edge Function と定時の処理が動いたとき、システムは会社ごと・1回ごとに処理の記録（始まり・終わり・結果・件数・エラー）を残す

### 電波のない間の送り直し（全部の機能の土台）

- **R-001-30** 電波のない間に端末で作った記録は、システムは端末にためておき、電波が戻ったら自動で送る
- **R-001-31** 同じ端末の ID の記録や RPC の呼び出しを二度送ったとき、システムは1件だけにする（二度目は何もしない）
- **R-001-32** まだ送れていない記録がある間、システムは画面にその件数を出し、送れるまで端末から消さない
- **R-001-33** 送れなかったとき、システムは端末のエラーとして、端末・時刻・中身を記録する

## 4. 範囲の外

- 会社が自分で登録する流れ、プランと課金、退会（007）
- 取引先・建物の登録（002）。外部の人の専用ページの画面（005）
- お知らせ（015）。001 の招待のメールは、Supabase のログインのメールで送る
- パスワードでのログイン、ほかのサービス（Google など）でのログイン

## 5. 決まっていないこと（推奨の案で進める）

| 点 | 推奨 | 理由 |
|---|---|---|
| ログインの方法 | メールのリンク（パスワードなし） | 現場のスタッフにパスワードを覚えてもらわなくて済む。パスワードの漏れもない |
| 招待のメールの送り主 | 試用の間は Supabase のログインのメールの仕組み。本番の前に、送信の専用のサービスに替える | 試用の間は費用がかからない。送れる数に上限があるので、会社が増える前に替える |
| 運営の操作の画面 | 試用の間は作らず、運営は Edge Function を呼ぶ小さな道具（コマンド）で会社を作る | 試用の会社は少ないので、画面を作るより早い。会社が増えたら 007 で画面にする |
| 電波のない間にためる場所 | 端末の IndexedDB | ブラウザの中で、大きな写真もためられる |
