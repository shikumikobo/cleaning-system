# 機能002：取引先・建物・部屋（要件）

状態：実装
作成：2026-11-16

全体の言葉と役割は [../product.md](../product.md)、変えない決まりは [../constitution.md](../constitution.md)、表と policy の型は [../data-model.md](../data-model.md)（002 の章）、CRUD は [../crud.md](../crud.md)（002 の章）。

## 1. ねらい

仕事を頼む側（取引先）と、清掃する物件（建物・部屋・場所）を、社長の頭や Excel ではなく、システムに持つ。建物ごとに「入り方・鍵の場所・駐車場・ゴミの日・管理人の連絡先・注意すること」（建物カルテ）を書いておき、初めての現場でもスタッフが迷わないようにする。後の機能（案件・見積・契約・写真・報告書・地図）は、ここで作る取引先・建物・部屋・場所を指す。

## 2. 利用者の話

- 社員として、管理会社・オーナーと担当者を登録・直したい。見積や請求の宛先にするため
- 社員として、建物を依頼元（管理会社）と所有者（オーナー）に結びつけて登録したい
- 社員として、建物カルテを書きたい。初めてのスタッフにも伝わるように
- スタッフとして、建物カルテをスマホで見たい。鍵の場所と入り方を現場で確かめるため
- 社員として、部屋と、写真や報告のひな形で使う場所（エントランス・階段 など）を登録し、使わなくなったものは「使わない」にしたい
- 社員として、取引先や建物を消したい。ただし、使われているものは消えず、理由が分かってほしい
- 外部の人（管理会社の担当者）として、自分に許された建物の名前と住所だけを見たい（鍵の場所などは見られない）

## 3. 受け入れ基準

### 取引先

- **R-002-1** 社員（`master.edit`）が取引先（種類：管理会社・オーナー、名前、住所、電話、メール、締め日、支払いの条件）を登録したとき、システムはそれを保存する
- **R-002-2** 名前が空・種類が決まった値以外・締め日が 1〜31 の外・メールが形に合わないならば、システムはその取引先を保存しない
- **R-002-3** 社員が取引先の担当者（名前・メール・電話）を登録・直す・消すとき、システムはそれを保存する（担当者は同じ会社の取引先にだけ付く）
- **R-002-14** 社員が取引先を消す RPC を呼んだとき、システムは取引先と、その担当者を一緒に論理削除する
- **R-002-15** 取引先に、消していない建物（依頼元または所有者として）・契約・請求書があるならば、システムはその取引先を消さず、理由（種類と件数）を返す

### 建物・カルテ

- **R-002-4** 社員が建物（名前・住所・依頼元の取引先・任意で所有者の取引先）を登録したとき、システムはそれを保存する
- **R-002-5** 別の会社の行を親にするならば、システムはそれを受け付けない（建物の依頼元・所有者、担当者・カルテ・部屋・場所の建物、所属の取引先、外部の人が見られる建物）
- **R-002-6** 位置（緯度・経度）は、両方入っているか両方空であり、緯度は -90〜90、経度は -180〜180 のとき以外、システムは建物を保存しない。位置を地図で直した印（`location_fixed`）は、初めは偽
- **R-002-7** 社員が建物カルテ（入り方・鍵の場所・駐車場・ゴミの日・管理人の連絡先・注意すること）を保存したとき、システムはそれを保存する。1つの建物に、消していないカルテは1つだけ
- **R-002-8** 会社の中の人（スタッフを含む）ならば、システムはカルテを読ませる。外部の人ならば、許された建物のものも含めて、カルテを読ませない
- **R-002-9** 外部の人ならば、システムは許された建物の名前と住所だけを読ませ、許されていない建物は読ませない。部屋・場所・取引先・担当者も読ませない
- **R-002-17** 建物に、先の予定（今日以降で、予定か実施中）の作業か、有効な契約があるならば、システムはその建物を消さず、理由（種類と件数）を返す
- **R-002-16** 社員が建物を消す RPC を呼んだとき、システムは建物と、そのカルテ・部屋・場所・外部の人の見られる建物を一緒に論理削除する

### 部屋・場所

- **R-002-10** 社員が部屋（部屋番号・階）を登録したとき、システムはそれを保存する。同じ建物に同じ部屋番号（消していない行）は2つ作らない。部屋は入居者の名前を持たない
- **R-002-11** 社員が場所（名前・並び順）を登録したとき、システムはそれを保存する。同じ建物に同じ名前（消していない行）は2つ作らない
- **R-002-12** 社員が部屋・場所を「使わない」にした・戻したとき、システムはそれを保存する。「使わない」の部屋・場所は、システムは新しく選ぶ候補に出さない（一覧には、印をつけて出す）
- **R-002-18** 社員が部屋・場所を消す RPC を呼んだとき、システムは、案件・写真・ひな形の項目から使われていなければ論理削除し、使われているならば消さず、「使わない」にして、そのことを返す

### 権限と守り

- **R-002-13** スタッフ・外部の人・運営・ログインしていない人ならば、システムは取引先・担当者・建物・カルテ・部屋・場所を作らせず、直させない（社員・管理者は書ける。スタッフと社員は取引先・建物・部屋・場所・担当者・カルテを読める）
- **R-002-19** 消す RPC（取引先・建物・部屋・場所）は、`master.edit` を持たない人（スタッフ・外部・別の会社の人・ログインしていない人）には、システムは実行させず、何も消さない
- **R-002-20** 画面や API から直接 `deleted_at` を書き込むならば、システムはそれを受け付けない（取引先・建物・カルテ・部屋・場所の消し方は RPC だけ）
- **R-002-22** 取引先・建物・カルテ・部屋・場所を作る・直す・消すとき、システムは履歴に残す（001 の変更の履歴。消すのは RPC なので source は rpc）

### 検索と画面

- **R-002-21** 取引先と建物の名前の一部を入れたとき、システムは部分一致で見つけ、消した行は出さない（名前の部分一致の索引を持つ）
- **R-002-23** 取引先・建物・部屋・場所を、スマホの幅で一覧・登録・編集・削除できる画面を、システムは持つ。入力は保存の前に検査し、候補の絞り込み（「使わない」を除く）と検索の並びは、画面の部品として決まっている
- **R-002-24** 消せなかったとき、システムは画面に、理由を日本語で（何が使っているか・いくつか）出す

## 4. 範囲の外

- 案件・見積・契約・作業・請求書の中身（003・004・010・012・011）。ここでは「使われていれば消さない」の仕組み（使われ方の登録）だけを作り、それぞれの機能が自分の表を登録する
- 建物の位置を住所から求める処理と地図（013）。ここでは位置の列と check だけ
- Excel・CSV からの一括の取り込み（014）
- ひな形（report_templates・template_items）の表と画面（009）。建物を消すときに一緒に消す仕組みだけを用意する
- 外部の人を招待する元の担当者の画面からの招待（001 の画面）。担当者は名前・連絡先を持つだけ

## 5. 決まっていないこと（推奨の案で進める）

| 点 | 推奨 | 理由 |
|---|---|---|
| 取引先の種類の値 | `management_company`（管理会社）、`owner`（オーナー） | data-model.md の「管理会社・オーナー」をコードの値にする |
| 締め日 | 1〜31。31 は月末 | 月によって末日が違うため、31 を「月末」として扱う |
| 支払いの条件 | 自由な文（例：月末締め翌月末払い） | 011 が使う形が決まるまで、文のまま持つ。011 の design で構造化するか決める |
| 使われているかの確かめ方 | 登録の表（`app.usage_refs`）に「どの表のどの条件が使っているか」を書き、消す RPC が見る | まだない表（案件・契約・請求書・写真・ひな形）を、後の機能が自分の migration で登録するだけで済む |
