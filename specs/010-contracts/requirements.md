# 機能010：清掃の契約・定期と単発（要件）

状態：実装
作成：2026-11-19

全体の言葉と役割は [../product.md](../product.md)、変えない決まりは [../constitution.md](../constitution.md)、表と policy の型は [../data-model.md](../data-model.md)（010・012 の章）、CRUD は [../crud.md](../crud.md)（010 の章）。001（権限・履歴）・002（取引先・建物）・004（見積。明細の繰り返し）・015（お知らせの仕組み）が前提。

## 1. ねらい

承認された見積を、清掃の契約にする。契約の中身（基本・オプション・特別清掃）が、いつ・どれだけ行い・いくら請求するかを持ち、そこから「予定（作業）」を2か月先まで自動で作る。金額や頻度が変わっても、昔の内容が残り、どの月にいくらだったかが分かる。請求書に載った月の中身は、あとから直せない。作業（`works`）と作業の金額・担当の最小の表は、予定を作るためにこの機能で作る（担当の割り当ての画面と実績は 012）。

## 2. 利用者の話

- 社員として、承認された見積から、開始日を決めて契約を作りたい。見積の明細が、そのまま清掃の中身になってほしい
- 社員として、契約の中身（金額・頻度）を、ある日から変えたい。変える前の内容は残り、その日より先の予定が新しい内容で作り直されてほしい
- 社員として、契約を終えたい。終わった日より後の予定は消えてほしい
- 社員として、これからの予定を一覧で見たい
- 管理者として、予定が毎朝自動で2か月先まで作られ、二重にならないでほしい。失敗した会社があっても、ほかの会社は止まらないでほしい
- スタッフは、契約の金額を見ない。自分が担当の作業だけ読める
- 管理会社の担当者（外部）は、許された建物の作業の「日」と「状況」だけを見る

## 3. 受け入れ基準

### 見積から契約を作る

- **R-010-1** `contract.edit` を持つ人が、承認された見積と開始日（終了日は任意）を選んで契約を作ったとき、システムは契約（状況：有効、元：見積）を保存する。取引先と建物は見積から写る。見積が定期なら契約は「定期」、それ以外は「単発」。承認でない見積・明細のない見積・開始日がない・終了日が開始日より前ならば、システムは作らず、理由を返す
- **R-010-2** 見積の明細は清掃の中身になる：基本 → 基本（毎月請求）、オプション → オプション（行った回ごと）、単発 → 特別清掃（行った回ごと）。金額は明細の金額、頻度は明細の繰り返し（なければ単発 `FREQ=DAILY;COUNT=1`）、起点（`valid_from`）は開始日。中身ごとに別の `service_key` が付く
- **R-010-3** 同じ見積から契約を2つ作らない。すでにあれば、同じ契約を返し、増やさない（DB の一意の索引も守る）
- **R-010-4** 取り込み（014）が、見積なしで契約（元：取り込み）を作れる。中身が1つもない・金額や繰り返しや種類が正しくない・別の会社の取引先ならば、システムは全部を作らない（半分だけ作らない）。元が見積なら見積が必ず要り、取り込みなら見積は付けない
- **R-010-5** `contract.edit` を持たない人（スタッフ・外部の人・運営・どこにも属さない人・ログインしていない人）は、契約を作れない。存在しない見積は、権限がないのと同じ扱いで断る

### 予定の作成（定時の処理）

- **R-010-6** 繰り返しは RRULE の文字列1つで持ち、毎週・隔週・毎月の第N曜日・月末・3か月に1回・単発などを日付に展開できる。扱えない形は、黙って違う予定を作らず、読めないとして扱う
- **R-010-7** 予定は、今日から2か月先まで、契約の期間と中身の期間（`valid_from`〜`valid_to`）の内側だけに作る。終えた契約・別の会社の中身は、元にしない
- **R-010-8** 定時の処理が二度動いても、同じ中身・同じ日の作業は重ならない（作った数が 0 になり、「すでにある」と数える）。手で足した作業は重なりに数えない
- **R-010-9** 作った作業は、中身の名前・建物・時刻を写し、状況は「予定」、処理の記録（`run_id`）が付く。中身に決まった担当があれば、初めの担当に入る
- **R-010-10** 行った回ごとに請求する中身（オプション・特別清掃）は、作業の金額（中身の金額）を作る。毎月請求の中身（基本）は作らない
- **R-010-11** 作業の会社は、元の中身の会社と必ず同じ。別の会社の中身・建物・処理の記録では作れない。定時の処理の関数は、サービスの鍵（`service_role`）だけが呼べる
- **R-010-12** 会社ごとに分けて回し、会社ごと・1回ごとに処理の記録（`job_runs`、種類 `schedule_works`）を残す（状況・件数・終了の時刻）。同じ会社で動いている最中は二重に始めない。30分を過ぎた古い記録は失敗で閉じる。1つの会社の失敗が、ほかの会社を止めない。繰り返しが読めない中身があっても、ほかの中身は作る

### 契約の変更・終了

- **R-010-13** `contract.edit` を持つ人が、今の中身を、適用日から変えられる（名前・金額・頻度・時刻）。システムは今の行を適用日の前日（`valid_to`）で閉じ、同じ `service_key` で新しい行（`valid_from` は適用日）を作る。古い行は金額そのままで残り、どの月にいくらだったかが分かる。適用日が今日より前・今の中身の開始日以前、変える項目がない・今と同じ値・値が正しくない（名前が空・金額が負や数でない・頻度が RRULE の形でない・終了の時刻が開始より前）ならば、変えず、理由を返す
- **R-010-14** 変えたとき、適用日以降の、まだ始まっていない予定（定時の処理が作ったもの）は取り消し（行は履歴として残る）、次の処理が新しい内容で作り直す。始まった・終わった作業と、手で足した作業は取り消さない。決まった担当は新しい行に引き継ぐ
- **R-010-15** 契約に終了日があれば、終了日より後の日からの変更はしない
- **R-010-16** 請求書に載った月以降に効く変更・終了は、システムはしない（理由：請求書に載っている）。請求書に載った作業の金額は直せない。請求書の明細の表（011）がまだなければ、載っていない扱いで飛ばす
- **R-010-17** `contract.edit` を持つ人が契約を終えたとき（終了日は省くと今日）、システムは状況を「終了」にし、開いている中身を終了日で閉じ、終了日より後の予定を取り消す。終了日までの予定は残る。終えた契約は読めるが、中身は変えられない。もう一度終えても、何もしない。終了日が開始日より前ならば終えない

### 権限・履歴

- **R-010-18** 契約・清掃の中身は、画面や API から直接作る・直す・消すことはできない（RPC だけ）
- **R-010-19** 契約・清掃の中身を読めるのは `amount.read` を持つ人（管理者・社員）。スタッフ・外部の人は読めない
- **R-010-20** 決まった担当は、`contract.edit` を持つ人が付ける・外せる（論理削除）。同じ人は二重に付けない。担当にできるのは同じ会社の社内の人だけ（外部の人・別の会社の所属は不可）。読めるのは会社の中の人で、スタッフは自分の行だけ
- **R-010-21** 作業を読めるのは、`work.assign` を持つ人（全部）、スタッフ（自分が担当の作業だけ）、外部の人（許された建物の、消していない作業の日と状況だけ。担当・金額は読めない）。担当の割り当てができるのは `work.assign` を持つ人だけ
- **R-010-22** 作業の金額は、1つの作業に1つ。読める・作る・直せるのは `amount.read` と `contract.edit` を持つ人。金額が負ならば保存しない
- **R-010-23** 作業は、画面や API から直接作れない・状況を直せない・消せない・日付を動かせない。直接直せるのは、状況が「予定」の間の時刻だけ。作業は、契約の中身か案件のどちらか1つを元に持つ（両方・どちらもなしは不可）。状況は予定・実施中・完了・行わず・取消のどれか
- **R-010-24** 別の会社の人は、契約・中身・作業を読めない・作れない・変えられない・終えられない（見つからないのと同じ扱い）。契約の作成・変更・作業の状況の変化は履歴に残る（source が rpc）
- **R-010-25** 契約のある取引先・有効な契約か先の予定のある建物は、消さない（002 の使われ方の登録）。契約が終わり先の予定もなければ、消せる

### 画面

- **R-010-26** 契約の一覧に、取引先・建物・種類・状況・期間が出て、状況と、取引先・建物の言葉で絞り込める
- **R-010-27** 頻度は日本語で出す（毎月 第2火曜・3か月に1回・毎週 月曜。単発は「1回だけ」）。時刻は 09:00〜11:00 の形
- **R-010-28** 契約の詳細に、清掃の中身（種類・名前・金額・請求の仕方・頻度・時刻・期間）が出て、変更で閉じた過去の内容は区別して出る。これからの予定が出る（取消は除く）
- **R-010-29** 承認された見積から契約を作る画面：見積と開始日を選ぶ（終了日は任意）。見積の未選択・開始日が空・終了日が開始日より前なら、RPC を呼ばずに理由を出す。RPC が断ったら日本語の理由を出し、作れたら契約の詳細へ移る
- **R-010-30** 中身の変更と契約の終了の画面：変えたところだけを RPC に渡し、確認のうえで呼ぶ。何も変えていなければ RPC を呼ばない。RPC が断った理由（請求書に載った月など）は日本語で出す。終了した契約には、変更・終了の操作を出さない
- **R-010-31** 予定の一覧に、今日以降の予定が日付・時刻の順に出て、建物と状況で絞れる。取消は、状況で選んだときだけ出る
- **R-010-32** `contract.edit` を持たない人には、契約を作る・変える・終える操作を出さない（出し分けのためだけ。判定は DB が行う）
- **R-010-33** 外部の人の専用ページに、許された建物の作業の「日」と「状況」の区画が出る（作業の名前・担当・金額は取らない。取消は除く）
