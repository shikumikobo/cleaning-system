# 機能016：売上と粗利（要件）

状態：実装
作成：2026-11-22

全体の言葉と役割は [../product.md](../product.md)、変えない決まりは [../constitution.md](../constitution.md)、表と policy の型は [../data-model.md](../data-model.md)（016 の `costs`、型 B）、CRUD は [../crud.md](../crud.md)（016 の章）。001（権限）・002（取引先・建物）・006（小口）・010（契約）・011（請求）が前提。

## 1. ねらい

契約・建物・取引先ごとに、月の売上（請求書の明細）と、費用（小口の出金と、手で入れる外注・材料などの費用）を集め、粗利を出す。前の月・前の年の同じ月との比べも出す。お金の数字なので、見られるのは管理者と社員（`amount.read`）だけで、スタッフ・外部の人には見せない。

## 2. 利用者の話

- 管理者・社員として、月を選ぶと、契約ごと・建物ごと・取引先ごとの売上・費用・粗利が分かってほしい
- 管理者・社員として、前の月・前の年の同じ月と比べて、増えたか減ったかが分かってほしい
- 社員として、外注や材料の費用を、月・建物（または契約）を決めて入れたい。間違えたら直したり消したりしたい
- 小口で払った分（確認済みのもの）は、入れ直さずに費用に入ってほしい
- スタッフ・外部の人は、売上も粗利も費用も見ない

## 3. 受け入れ基準

### 売上

- **R-016-1** 売上は、発行した請求書（状況が 発行・送付・一部入金・入金済み）の、消していない明細の金額（税抜）。請求書の請求月（`period`）の月に入れる。入金の有無・日では動かない
- **R-016-2** 下書き・取消・消した請求書の明細は、売上に入れない。下書きの分は、売上とは別の「下書き（見込み）」の列に出す
- **R-016-3** 明細の元から、契約と建物を決める。契約の中身の元は、その契約と建物。作業の元は、その作業の建物と、契約の作業ならその契約。案件の元は、その案件の建物（契約はなし）。取引先は、請求書の取引先

### 費用

- **R-016-4** 小口の出金のうち、確認済み・締め済みのものを、費用（小口）に入れる。出金の日の月に入る。建物は、出入りの建物、なければ作業の建物。契約は、作業が契約の作業のときだけ入る。下書き・入金（渡した現金）・消した行は入れない
- **R-016-5** 手で入れた費用（`costs`）は、その月・建物・契約・種類（外注・材料・その他）・金額のまま、費用に入る。消した費用は入れない。建物が空で契約があれば、契約の建物に入れる。建物も契約も空の費用は、「共通」として取引先・建物のない行になる
- **R-016-6** 粗利は 売上 − 小口の費用 − 手で入れた費用（外注・材料・その他）。月 × 取引先 × 建物 × 契約の行ごとに、売上・下書き・小口・外注・材料・その他・粗利を出せる（view）。下書きは粗利に入れない
- **R-016-7** 契約ごと・建物ごと・取引先ごとに集めた月の合計は、どの切り方でも同じ全体の合計（売上・費用・粗利）と一致する。建物・契約が決められない分は、「建物なし」「契約なし」の行に入り、消えない
- **R-016-8** 前の月と前の年の同じ月との比べを出す。差（円）と増減の率（％）。比べる側が 0 のときは、率は出さない（0 で割らない）

### 費用の入力

- **R-016-9** `invoice.edit` を持つ人は、費用を作る・直す・消す（論理削除）ことができる
- **R-016-10** 月（その月の1日に直す）・種類（外注・材料・その他）・金額（1円以上の整数）が正しくなければ保存しない。建物と契約の両方を指すときは、契約の建物と同じでなければ保存しない
- **R-016-11** 別の会社の建物・契約を指す費用は、保存しない
- **R-016-12** 費用を作る・直す・消すとき、システムは履歴に残す（001 の変更の履歴）
- **R-016-13** 建物を指す費用（消していないもの）がある建物は、システムは消さず、理由（`has_costs`）を返す（002 の `app.usage_refs` の登録が効く）。費用を消せば、建物を消せる

### 権限と守り

- **R-016-14** `amount.read` を持つ人（管理者・社員）だけが、売上と粗利の view と費用を読める。スタッフ・外部の人・運営（許可のないとき）・ログインしていない人は、0 行しか返らない。スタッフが自分の小口の出金を、費用として読むことはない
- **R-016-15** `invoice.edit` を持たない人は、費用を作る・直す・消すことができない（`amount.read` だけの人を含む）
- **R-016-16** 別の会社の売上・粗利・費用は、読めない・直せない
- **R-016-17** 集計の view は、見る人の権限で絞る（`security_invoker`）。請求書・明細・契約・小口の RLS を通るので、view に別の抜け道は作らない

### 速さ

- **R-016-18** 集計は、会社と月で絞る形で読む。請求書は `(tenant_id, period)`、小口の出金は `(tenant_id, entry_date)`、費用は `(tenant_id, month)` の索引が効き、会社と月を指定した読みは、これらの索引を使う（全部の行を読まない）

### 計算・画面

- **R-016-19** 契約ごと・建物ごと・取引先ごとの集め方、合計、粗利率、前の月・前の年との比べ、名前の付け方（建物なし・契約なし・共通）は、画面の部品（純粋な関数）で持つ。DB の view の合計と同じテストのデータで一致する
- **R-016-20** 費用の入力は、保存の前に検査する（月・種類・金額・建物か契約）。RPC でなく直接の書き込みなので、DB が断った理由は日本語で出す
- **R-016-21** 画面（スマホの幅で使える）は、月の売上と粗利（契約・建物・取引先の切り替え）、前の月・前の年との比べ、費用の入力・一覧・直す・消すを持つ。`invoice.edit` を持たない人には、費用を作る・直す・消す操作を出さない（出し分けのためだけ。判定は DB が行う）。`amount.read` を持たない人は、数字の代わりに権限がないことを出す

## 4. 範囲の外

- 税込・税抜の合わせ込み。売上は税抜、小口の出金は入力した金額（税込のことが多い）のまま足す。費用の税の扱いは、人が決める
- 月の途中の按分（建物をまたぐ費用の割り振り）。1件の費用は、1つの建物か契約に付ける
- 作業の予定と実績（012）から人件費を出すこと。012 の表への外部キー。費用の `work_id` の列
- 前の月までを毎晩の集計の表にすること（遅くなったときの手段。data-model.md）
- 会計ソフトへの書き出し。経営の目標・予算との比べ

## 5. 決まっていないこと（推奨の案で進める）

| 点 | 推奨 | 理由 |
|---|---|---|
| 売上に入れる請求書 | 発行以降（入金前でも）。下書きは別の列 | 発行した請求書は、直せない確定した金額。入金の遅れは粗利と別の話 |
| 売上の月 | 請求書の請求月 | 毎月請求の契約と、その月の作業・案件を同じ月で見るため |
| 小口の費用の入れ方 | 確認済み・締め済みの出金（出金の日の月） | 確認前は金額が直ることがある。下書きを足すと、締めるたびに数字が動く |
| 手で入れた費用に建物も契約もない | 「共通」として許す | 事務所の経費などを入れられるように。粗利の全体には入る |
| 契約を元にしない作業・案件の売上の契約 | 空（契約なし） | 案件は契約がないので |
