# 機能013：地図（要件）

状態：実装
作成：2026-11-17

全体の言葉と役割は [../product.md](../product.md)、変えない決まりは [../constitution.md](../constitution.md)、表と policy の型は [../data-model.md](../data-model.md)（002・012 の章）、CRUD は [../crud.md](../crud.md)（013 の章）。002（建物。位置の列）・012（実績。位置・距離の列と開始・終了の RPC）・015（お知らせの仕組み）・001（権限・会社）が前提。

## 1. ねらい

建物の住所から位置（緯度・経度）を求めて保存し、建物と、その日の作業の場所を地図に出す。位置がずれていたら、社員が地図で直せる。スタッフは、スマホの地図アプリで道案内を開ける。作業の開始・終了のときだけ、スタッフの了承を得て位置を記録し、建物から離れていれば社員に知らせる。記録した位置は 90 日で消す。現場では、建物カルテと地図を一緒に見る。

位置を求める外の API（地図の検索）は、配備のときに人が選ぶ。ここでは差し替えられる口（adapter）にして、テストは偽の口で行う。API のキーは、コードにも仕様にも書かない（配備の環境変数）。

新しい表は作らない（data-model.md の 013 の行）。建物に、位置を求めるのに失敗した印の列 1 つ（`geocode_failed_at`）だけ足す。

## 2. 利用者の話

- 社員として、建物を登録したら、住所から位置が自動で入ってほしい。ずれていたら、地図を押して直したい。直した位置は、自動で上書きされたくない
- 社員として、今日の作業がどこであるのかを地図で見たい。建物の地図も見たい
- スタッフとして、現場へ行くときに、スマホの地図アプリで道案内を開きたい。着いたら、建物カルテ（入り方・鍵・駐車場・注意）と地図を見たい
- スタッフとして、開始・終了を押すときに、位置を記録するかどうかを選びたい。記録したくなければ、位置なしで押せてほしい。常に位置を追われたくない
- 社員として、建物から離れた場所で開始・終了が押されたら、知らせてほしい（付け忘れ・押し間違いの確認）
- 管理者として、記録した位置が残り続けないでほしい（90 日で消える）

## 3. 受け入れ基準

### 住所から位置を求める・直す

- **R-013-1** 建物の位置（`lat`・`lng`）は、両方があるか両方空（002 の check）。範囲外（緯度 ±90・経度 ±180 を超える）は保存できない
- **R-013-2** 位置を求める対象は、位置が空で、地図で直していない（`location_fixed = false`）建物。消した建物・失敗から 7 日以内の建物は対象にしない。1 回の処理で 1 社あたり最大 50 件（`limit`）
- **R-013-3** 求めた位置は、保存の時点でも「位置が空で、直していない」ときだけ書く。その間に人が位置を直していたら、上書きしない
- **R-013-4** 住所が見つからない・外の API が失敗したとき、位置は空のまま、`geocode_failed_at` に時刻を入れ、7 日は再試行しない。次の会社の処理は止めない
- **R-013-5** 住所を変えたとき、地図で直していない建物は位置を空に戻し、失敗の印も消す（求め直しの対象になる）。地図で直した建物は、位置を残す
- **R-013-6** 地図で直せるのは `master.edit` の人だけ（直接の更新。列の権限）。直すと `location_fixed` が true。`master.edit` のない社員・外部の人は直せない。ほかの会社の建物は直せない
- **R-013-7** 「住所から求め直す」は `master.edit` の人が、位置を空に、`location_fixed` を false に戻す操作で行う（次の処理で求め直される）
- **R-013-8** 定時の処理（Edge Function `geocode-buildings`）は、service_role のキーを持つ呼び出しだけが呼べる。会社ごとに分け、会社ごと・1 回ごとに `job_runs`（種類 `geocode_buildings`）に記録する。同じ会社で動いている最中なら飛ばす。1 つの会社の失敗はほかを止めない。記録・エラー・戻り値に鍵を出さない
- **R-013-9** 位置を求める外への口は adapter（`Geocoder`）で差し替えられる。何も選ばれていないときは、「口が未設定」で失敗にし、位置を作らない。テストは偽の口で行う。1 件ごとに待ち時間を置く（外の API の利用の決まりを守るため。待ち時間は引数）
- **R-013-10** 画面から 1 件だけ求める入口（同じ Edge Function。ログインの鍵つき）は、`master.edit` の人が、自分の会社の建物の住所についてだけ呼べる。結果は候補の位置で、保存は画面が行う（直接の更新）。権限のない人・ほかの会社の建物・存在しない建物は、同じ「権限がない」で断る
- **R-013-11** 日本の住所検索の口（国土地理院の住所検索）は、応答（GeoJSON）の先頭の点を `{lat, lng}` に読み替える。点がなければ「見つからない」。応答が壊れていても落ちない

### 位置の記録（開始・終了）

- **R-013-12** 開始・終了（`start_work`・`finish_work`）は、位置（緯度・経度）を任意で受け取る。渡さなければ、位置なしで今までどおり記録できる（了承しなかった場合）
- **R-013-13** 位置が片方だけ、または範囲外のときは、記録せず `{ok:false, reason:'invalid_location'}` を返す
- **R-013-14** 開始の位置は `start_lat`・`start_lng`、終了の位置は `end_lat`・`end_lng` に入る。位置を渡さなかった側は空のまま。同じ uuid の開始の二度目は、位置も知らせも増やさない
- **R-013-15** 建物に位置があり、位置が渡されたとき、建物との距離（m。四捨五入）を求める。`distance_m` は開始・終了のうち大きい方、`distance_warning` は 300 m を超えたかどうか（どちらかが超えれば true）。建物に位置がない・位置を渡さなかったときは、距離は空・警告なし（2 回目の終了で、開始の分は残る）
- **R-013-16** 距離が 300 m を超えたとき、その会社の `work.assign` を持つ有効な所属の人（記録した本人を除く）に、お知らせ（種類 `work_far`）の「送る前」を作る（015 の `app.enqueue_notification`）。重複の印は「実績の id＋開始か終了」。リンクは `/schedule/work/?id=<作業>`。超えていない・位置なし・建物に位置なしのときは作らない。通知の失敗は記録を止めない
- **R-013-17** 実績の位置の列は、本人と `work.assign` の人だけが読める（012 の型 C1 のまま）。ほかの会社の人・外部の人・担当でない社員は読めない。RPC 以外から位置を書き込めない
- **R-013-18** 位置を記録するのは、開始・終了のときだけ。それ以外のとき（予定を見る・地図を見る）に、位置を取りに行かない。位置を常に追う処理は作らない

### 90 日で消す

- **R-013-19** 実績の開始から 90 日を過ぎた位置の列（`start_lat`・`start_lng`・`end_lat`・`end_lng`）を空にする。距離（`distance_m`）・警告（`distance_warning`）・開始・終了の時刻・行そのものは残す。90 日以内のものは消さない
- **R-013-20** 定時の処理（Edge Function `purge-locations`）は、service_role のキーを持つ呼び出しだけが呼べる。会社ごとに分け、会社ごと・1 回ごとに `job_runs`（種類 `purge_locations`）に記録する。同じ会社で動いている最中なら飛ばす。1 つの会社の失敗はほかを止めない。ほかの会社の実績には触れない

### 画面

- **R-013-21** 地図の画面（`/map/`）は、位置のある建物を地図に出す。位置のない建物は、一覧に「位置なし」と出す。地図の下に、地図の元データの帰属（© OpenStreetMap contributors）を必ず出す
- **R-013-22** 日付を選ぶと、その日の作業（取消を除く）の建物に印が付き、作業の一覧（時刻・題名・建物）が出る。印か一覧を押すと、その建物が選ばれる
- **R-013-23** 選んだ建物の下に、建物カルテ（入り方・鍵の場所・駐車場・ごみの日・管理者の連絡・注意）と、「道案内を開く」「建物のカルテへ」のリンクが出る
- **R-013-24** 道案内のリンク（URL）は、建物に位置があれば緯度・経度で、なければ住所で作る（スマホの地図アプリが開く `https://www.google.com/maps/dir/?api=1&destination=…` 形式。外部へ出るのは URL を開いたときだけ）。住所や名前の特殊な文字は符号化する
- **R-013-25** 位置を直す画面は、`master.edit` の人にだけ出す。地図を押すか、住所から求めた候補を使って位置を決め、「この位置で保存」で保存する（直した印が付く）。「住所から求め直す」も同じ画面から行う。位置を保存する前に、今の位置と新しい位置の違いが分かる
- **R-013-26** 自分の予定（`/schedule/mine/`）の各作業から、地図・道案内・建物のカルテへ行ける
- **R-013-27** 自分の予定の「開始」「終了」を押すと、先に「位置を記録しますか」と尋ねる（記録して押す／位置なしで押す／やめる）。毎回尋ね、了承の選びを端末に残さない。「位置なしで押す」では位置を取りに行かない
- **R-013-28** 「記録して押す」で位置を取れなかったとき（拒否・時間切れ・非対応）は、位置なしで記録し、そのことを画面に出す。電波がなくても、位置を付けて送り箱にためられる。二度押しても 1 回
- **R-013-29** 地図の部品（ライブラリ）は、地図を開く画面だけで読み込む（ほかの画面を重くしない）。地図のタイルの URL は、環境の設定で差し替えられる（既定は OpenStreetMap の標準のタイル）
