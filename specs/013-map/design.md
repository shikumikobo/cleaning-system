## 2. 位置の扱い（trigger と関数）

- `app.buildings_location_guard()`（`buildings` の更新の前）
  - 位置が変わったとき：人（`auth.uid()` がある）が空でない位置にしたら `location_fixed = true`、失敗の印を消す。定時の処理（service_role。`auth.uid()` なし）が書いたときは印を付けない
  - 住所だけが変わったとき：直していない建物は位置を空に戻し、失敗の印を消す（求め直しの対象）。直した建物は位置を残す
  - 住所と位置を一緒に変える更新は、渡した位置を使う（フォームが古い位置をそのまま送ってくる更新と、位置を直す更新を区別するため、位置が変わらなければ「住所だけ」とみなす）
- `app.distance_m(lat1, lng1, lat2, lng2)`：ハーバーサイン（地球の半径 6371008.8 m）、m の整数に四捨五入。空があれば空。画面の `distanceM`（`lib/map/geo.ts`）と同じ式
- `app.map_far_threshold_m()`：建物から離れているとみなす距離。300 m

## 3. 住所から位置を求める（定時の処理）

| もの | 中身 | 基準 |
|---|---|---|
| `geocode_tenants()` | 対象の建物のある会社（止めた会社を除く）。service_role だけ | R-013-2・8 |
| `geocode_start(p_tenant)` | `job_runs`（種類 `geocode_buildings`）を始める。同じ会社で動いていれば null。30 分を過ぎた古い記録は失敗で閉じる。部分一意索引で二重を防ぐ | R-013-8 |
| `geocode_pending(p_tenant, p_limit)` | 位置が空・直していない・消していない・失敗なし（または 7 日以上前）の建物の `id`・`address`。古い順。`p_limit` は 50 | R-013-2 |
| `geocode_apply(p_tenant, p_building, p_lat, p_lng)` | 保存の時点でも「位置が空で直していない」ときだけ書く。書いたら true。範囲外は `22023` | R-013-3 |
| `geocode_fail(p_tenant, p_building)` | 失敗の時刻を入れる | R-013-4 |
| `geocode_finish(...)` | 記録を `success`・`failure` で閉じる。件数（`geocoded`・`not_found`・`errors`・`superseded`）を `counts` に | R-013-8 |
| `geocode_target(p_building)` | ログインした人用。`master.edit` を確かめ、建物の住所を返す。行がない・権限がない・ほかの会社は同じ `42501` | R-013-10 |

- Edge Function `geocode-buildings`（判断は `supabase/functions/_shared/geocode.ts`、Deno にだけ依存する口は `geocode_adapters.ts`）
  - **定時**：service_role のキーつきの呼び出し。会社ごとに「記録を始める → 対象を読む → 1 件ずつ求めて保存（件の間に待ち時間 1.1 秒）→ 記録を閉じる」。見つからなければ失敗の印を付ける。通信の失敗は印を付けず（次の処理でもう一度）、3 回続いたらその会社を止める。口が未設定ならその会社を失敗にする（建物には印を付けない）。1 つの会社の失敗はほかを止めない
  - **画面から 1 件**：ログインの鍵つきで `{building_id}`。`geocode_target` で権限を確かめ、候補の位置 `{found, lat, lng}` を返す。保存はしない（画面が地図で確かめてから、直接の更新で保存）
- **位置を求める口（adapter）**：`interface Geocoder { geocode(address): Promise<{lat,lng} | null> }`。環境変数 `GEOCODER` で選ぶ。未設定・知らない名前は `GeocoderNotConfigured`（処理は失敗、位置は作らない）。いまある口は国土地理院の住所検索（`GEOCODER=gsi`。キー不要。日本の住所）。ほかの API（有料の地図会社など）は、同じ `Geocoder` を実装して `createGeocoder` に 1 行足すだけ。API のキーはコードに書かず、配備の環境変数に入れる
- 国土地理院の口の応答は、GeoJSON の配列で、先頭の点の座標は `[経度, 緯度]`（これは外の API の仕様の私の理解で、実際の呼び出しは配備のときに確かめる）

## 4. 位置の記録（開始・終了）

- `start_work(p_id, p_work_id, p_started_at, p_device_id, p_client_created_at, p_lat, p_lng)`・`finish_work(p_id, p_work_id, p_ended_at, p_lat, p_lng)`：012 の関数に、位置の引数（任意）を足した。位置を渡さなければ、012 のとおり
  - 位置は両方か両方空・範囲内。違えば `{ok:false, reason:'invalid_location'}`（実績も状況も変えない）。同じ uuid の二度目（`already`）は検査の前に返す（位置も知らせも増やさない）
  - 建物に位置があり、位置が渡されたとき、距離を求める。開始は `distance_m`・`distance_warning`（300 m 超）を入れる。終了は、`distance_m` を開始と終了のうち大きい方に、`distance_warning` をどちらかが超えていれば true にする
  - 離れていたら `app.notify_work_far` が、その会社の `work.assign` を持つ有効な所属の人（記録した本人を除く）に `app.enqueue_notification` で「送る前」を作る。重複の印は `<実績の id>:start|finish`。終了のお知らせは、終了の位置そのものが離れているときだけ（開始で知らせた分を重ねない）。お知らせが作れなくても、記録は止めない（`exception when others`）
- 画面（`/schedule/mine/`）は、押したら先に「位置を記録しますか」を出す（`ConsentChoice`：記録して押す／位置なしで押す／やめる）。毎回尋ね、了承の選びは端末に残さない。取るのは「記録して押す」の 1 回だけ（`getCurrentPosition`。`watchPosition` は使わない）。取れなければ位置なしで記録し、理由を出す。位置は送り箱の引数（`p_lat`・`p_lng`）に入れてためる（電波がなくても、位置つきで残る）

## 5. 位置を 90 日で消す（定時の処理）

- `purge_locations_tenants()`・`purge_locations_start`・`purge_locations_run(p_tenant)`・`purge_locations_finish`：service_role だけ。`purge_locations_run` は、その会社の、開始が 90 日より前の実績の位置の 4 列を空にし、空にした数を返す（行・時刻・距離・警告は残す。消した行や、開いたままの実績も対象）
- Edge Function `purge-locations`（判断は `_shared/purgeLocations.ts`）：会社ごとに記録を残す（種類 `purge_locations`）。同じ会社で動いていれば飛ばす

## 7. 地図のタイルの利用条件

- 既定のタイルは OpenStreetMap の標準のタイル（`https://tile.openstreetmap.org/{z}/{x}/{y}.png`）。環境変数 `NEXT_PUBLIC_MAP_TILE_URL`（`https://` で `{z}`・`{x}`・`{y}` を含むもの）で差し替えられる
- OpenStreetMap の標準のタイルの利用条件（Tile Usage Policy）：帰属表示（© OpenStreetMap contributors と著作権ページへのリンク）を必ず出す（地図の下に出している）。一括の取得・大量のアクセスをしない。ブラウザが送る参照元（Referer）を消さない。サーバーは善意の運営で、いつでも利用を制限されうる
- 試用・少人数の間は既定のままで足りる。会社を増やすときは、タイルの提供元（有料のタイルの提供・自前の配信）を選んで、環境変数で差し替える（人の決定。費用が絡む）
- 道案内は、URL を作って開くだけ（Google マップ・Apple マップ）。こちらから地図会社の API を呼ばない

## 8. 使われているものは消さない

建物の位置は建物の列で、新しい参照を作らない（`app.usage_refs` の行は足さない）。実績は作業に付くだけで、建物を直接は指さない（012）。

## 10. 決めたこと

| 決めたこと | 理由 | ほかの案 |
|---|---|---|
| 建物から離れているとみなす距離は 300 m | 都市部のスマホの位置は数十 m〜100 m ずれる。大きな建物の敷地の端と入口でも 300 m は超えにくい。付け忘れ・押し間違いの確認が目的で、止めない（推測。試用で聞く） | 100 m（誤報が多い）／会社ごとの設定（範囲が広がる） |
| 距離を超えても、開始・終了は止めずに記録する。知らせるだけ | 現場の動きを止めない。仕様は「知らせる」 | 断る |
| `distance_m` は開始・終了のうち大きい方、警告はどちらか | 列が 1 つずつしかないので、確認する人が気にする方（離れた方）を残す | 終了の値で上書き（開始の警告が消える） |
| 終了のお知らせは、終了の位置そのものが離れているときだけ | 開始で知らせた分を重ねると、同じ作業で 2 通になる | 警告が付いていれば終了でも知らせる |
| お知らせの宛先は、その会社の `work.assign` を持つ有効な所属（記録した本人を除く） | 「社員に知らせる」。担当の社員ごとの割り当てはなく、予定を見る権限と同じ人 | 作業の担当だけ（社員とは限らない） |
| 位置の了承は、押すたびに尋ねる。端末に残さない | 常時の追跡を避ける仕様。残すと「いつの間にか記録される」 | 「いつも記録する」の選び（便利だが、了承の意味が薄れる） |
| 位置は了承した 1 回だけ `getCurrentPosition` で取る。`watchPosition` は作らない | 開始・終了のときだけ記録する仕様 | 開始〜終了の間の経路（仕様の範囲外） |
| 位置を渡さない（了承しない・取れない）開始・終了も、012 のとおり記録できる | 了承しなくても仕事ができること（仕様） | 位置を必須にする |
| 位置が片方だけ・範囲外は、記録せず `invalid_location` | 端末の不具合で変な位置が入るのを防ぐ。位置なしで押し直せる | 位置だけ捨てて記録する（端末の不具合に気づけない） |
| 失敗の印の列 `geocode_failed_at` を建物に足す。新しい表は作らない | 求められない住所が毎回先頭を占めないため。data-model.md の「新しい表は作らない」は守る | 表を作る／印なしで毎回求める |
| 失敗は 7 日おいて求め直す。通信の失敗は印を付けない | 住所の直しや地図の更新で見つかるようになることがある。通信の失敗は住所のせいではない | 求め直さない／毎日 |
| 地図で直した位置は、定時の処理が上書きしない。住所を変えても残す | 人が確かめた位置のほうが、機械の推測より正しい。住所を直しても、直した位置が消えるのは意図しない | 住所の変更で位置も空に戻す |
| 位置を直す人は `master.edit`（建物の直接の更新） | crud.md の 013（画：master.edit）。新しい RPC を作らない | 専用の RPC |
| 住所から求める入口は、候補を返すだけにし、保存は画面が行う | 「ずれたら地図で直せる」。確かめずに保存すると、間違った位置が入る | EF が直接保存 |
| 位置を求める口が未設定のときは、処理を失敗にし、建物に失敗の印を付けない | 口がないのは設定の問題で、住所のせいではない | 位置なしで成功にする |
| 国土地理院の住所検索の口を 1 つ付けた（既定では選ばない） | 日本の住所で、キーが要らず、確かめやすい。選ぶのは配備のときに人が決める | 口を付けない（テストが偽の口だけになる） |
| 1 件ごとに 1.1 秒の待ち時間 | 外の API の利用の決まり（連続の呼び出しを避ける）を守る。1 社 50 件で約 1 分 | 待たない |
| 地図は Leaflet（動的に読み込む）。印は div の印 | 信頼できる地図の部品。画像を使わず、バンドラーで画像の道がずれない | 自作（地図の操作が大変）／MapLibre（ベクタのタイルが要る） |
| 道案内は URL を作るだけ | 仕様。地図会社の API を呼ばない | アプリ内の経路探索 |
| 位置を 90 日で空にするのは、列だけ。距離・警告・行・時刻は残す | data-model.md の 012「位置は 90 日で消す（距離と警告は残す）」 | 行ごと消す |
| 90 日の起点は実績の開始 | 実績ごとに 1 つの日付で決められ、開いたままのものも決まる | 位置を記録した日（開始と終了で別になる） |
