# 機能005：ファイルと専用ページ（要件）

状態：実装
作成：2026-11-16

全体の言葉と役割は [../product.md](../product.md)、変えない決まりは [../constitution.md](../constitution.md)、表と policy の型は [../data-model.md](../data-model.md)（005 の章）、CRUD は [../crud.md](../crud.md)（005 の章）。

## 1. ねらい

建物ごとに、契約書・図面・見積の PDF などのファイルを会社のものとして置き、社員だけが見るものと、取引先の担当者（外部の人）にも見せるものを分ける。外部の人は、ログインすると「専用ページ」に入り、許された建物の名前と住所、その建物の共有されたファイルだけを見る。見積・報告書・作業の日と状況は、004・009・012 ができたら、同じページに足せる形にしておく。

## 2. 利用者の話

- 社員として、建物にファイル（契約書・図面・見積の PDF など）を上げ、あとから開きたい。紙やメールを探さないため
- 社員として、ファイルごとに「外部に共有する」のオンとオフを選びたい。見せてよいものだけを見せるため
- 社員として、間違えて上げたファイルを消したい
- 外部の人（管理会社・オーナーの担当者）として、ログインしたらすぐ、自分に許された建物と、共有されたファイルだけを見たい
- 外部の人として、見せてもらえないもの（鍵の場所・金額・担当・ほかの建物）が見えなくてよい
- 管理者として、外部の人に、見せてはいけないものが見えないことを、DB のテストで確かめたい

## 3. 受け入れ基準

### ファイルの行

- **R-005-1** 社員（`master.edit`）がファイル（建物・名前・種類・大きさ・置き場所のパス）の行を作ったとき、システムはそれを保存する。共有（`shared_external`）の初めの値は、共有しない
- **R-005-2** 置き場所のパスが、その会社の `<tenant_id>/files/` で始まらないか、名前が空か、大きさが負か、同じ会社の消していない行にすでにあるパスならば、システムはその行を保存しない
- **R-005-3** 別の会社の建物を指すならば、システムはその行を保存しない
- **R-005-4** 社員が案件・見積のつなぎ（`request_id`・`quote_id`）を付けても付けなくても、システムは行を保存する（案件・見積の機能ができるまでは、列だけで外部キーは付けない）
- **R-005-5** 社員が名前・共有・つなぎ・消す（論理削除）を直したとき、システムはそれを保存する。建物・置き場所のパス・種類・大きさは、作ったあとは直させない
- **R-005-6** 会社の中の人（スタッフを含む）ならば、システムはその会社のファイルの行を読ませる。`master.edit` を持たない人（スタッフ）には、作らせず・直させない
- **R-005-7** 別の会社のファイルの行は、読めず・書けず・数も分からない（ほかの表と同じ型の漏れのテストにも入る）

### 置き場所と期限つきの URL

- **R-005-8** システムは常に、ファイルを非公開の置き場所の `<tenant_id>/files/…` に置く。外部の人は、置き場所を直接は読めず、上げられない（URL で渡す）
- **R-005-9** 行が見える人が、ファイルの ID（複数）を渡したとき、システムは見えるファイルの期限つきの URL を、1回の呼び出しでまとめて作って返す。期限は呼び出しで指定でき、指定がなければ 10 分、最長 1 時間
- **R-005-10** 見えない行（別の会社・共有されていない・許されていない建物・消した行）の ID が混ざっているならば、システムはその URL を作らず、「見つからない」と同じ扱いにする（存在を探らせない）。見える分は返す
- **R-005-11** ログインしていない呼び出しならば、システムは URL を作らず、断る
- **R-005-12** 渡された ID が空・多すぎる（100 より多い）・uuid の形でないならば、システムは URL を作らず、断る

### 上げる順と掃除

- **R-005-13** システムは常に、置き場所に上げてから行を作る。行を作れなかったときは、上げたファイルを消そうとする（消せなくても、掃除が拾う）。上げられなかったときは、行を作らない
- **R-005-14** 掃除の処理（定時）のとき、システムは、`<tenant_id>/files/` の下にあって、生きている行（消していない行）も、猶予の間に消した行も持たないファイルを、消す対象にする。猶予（初めは 1 日）の間に作られたファイルは、上げている途中かもしれないので対象にしない
- **R-005-15** 掃除の処理のとき、システムは、猶予より前に作った行で、置き場所にファイルがないものを論理削除する
- **R-005-16** システムは掃除の処理で、`<tenant_id>/files/` の外のファイル（写真・レシートなど）と、ほかの会社のファイルを、消す対象にしない
- **R-005-17** 掃除の処理は、会社ごと・1回ごとに処理の記録（`job_runs`。種類 `sweep_files`）を残す。同じ会社の掃除は同時に1つだけ動く。1つの会社の失敗は、ほかの会社を止めない。記録に鍵や長い文字列を残さない
- **R-005-18** 掃除の処理の関数は、service_role だけが呼べる。ログインした人（管理者を含む）と、ログインしていない人は呼べない

### 外部の人の専用ページ（読む決まり）

- **R-005-19** 外部の人ならば、システムは、許された建物の、共有された（`shared_external`）消していないファイルの行だけを読ませる。共有していないもの・許されていない建物のもの・消したものは読ませない
- **R-005-20** 社員が共有をオフにしたとき、システムはすぐに、外部の人がそのファイルを読めず、URL も作れないようにする
- **R-005-21** 外部の人ならば、システムはファイルの行を作らせず・直させず・消させない
- **R-005-22** 外部の人ならば、システムは許された建物の名前と住所を読ませる。許されていない建物は読ませない。ほかの会社の外部の人にも、この会社のファイルと建物を読ませない
- **R-005-23** 外部の人ならば、システムは建物カルテ・部屋・場所・取引先・担当者・金額（案件・作業・見積の金額）・担当・作業の実績と位置・小口現金とレシートを、読ませない。まだ表がない機能の分は、表ができたとき同じテストが自動で確かめる
- **R-005-24** 外部の人ならば、システムは、登録された全部の表のうち、外部に見せる型（D）の表と、自分の所属・自分に許された建物・自分の会社の行だけを、読ませる。外部に見せる型の表から読める行は、すべて自分に許された建物のものである
- **R-005-25** 外部の人が専用ページで見られる範囲は、建物の名前と住所、その建物の共有されたファイルであり、画面は位置・取引先・カルテを取り出さない

### 専用ページ（画面）

- **R-005-26** 外部の人がログインして最初の画面（ホーム）を開いたとき、システムは専用ページ（`/portal/`）に移す。社内の人はいつもの社内のホームのままにする
- **R-005-27** 専用ページは、許された建物の一覧（名前と住所）と、建物ごとの共有されたファイルの一覧を出す。許された建物がなければ「見られる建物がありません」と出す。ファイルは、名前を押すと期限つきの URL で開く
- **R-005-28** 専用ページは、建物ごとの中身を「区画」の登録簿から組み立てる。見積・報告書・作業の日と状況は、004・009・012 の機能が登録簿に区画を1つ足せば、同じページに出る。区画は、建物の ID と外部の人の読める範囲だけで描く
- **R-005-29** 外部の人は、専用ページから、見積の承認などの状況を書き換える操作を持たない（承認は、取引先から返事をもらった社員が記録する）

### 社内の画面（建物ごとのファイル）

- **R-005-30** 社内の画面は、建物を選ぶと、その建物のファイル（消していないもの）を、新しい順に、名前・種類・大きさ・共有の状態・上げた日で一覧にする
- **R-005-31** 社員がファイルを選んで上げたとき、画面は置き場所に上げてから行を作り（R-005-13）、一覧に加える。名前が空か、長すぎる（255 字より長い）なら、上げない
- **R-005-32** 社員が共有のオンとオフを切り替えたとき、画面はその行の `shared_external` を直す
- **R-005-33** ファイルの名前を押したとき、画面は期限つきの URL（R-005-9）を取って開く
- **R-005-34** 社員がファイルを消したとき、画面はその行を論理削除し、一覧から外す
- **R-005-35** `master.edit` のない人には、画面は上げる・共有・消すの操作を出さない（見せ方だけ。判定は DB）
- **R-005-36** 大きさと種類は、日本語の短い表記（例：1.5 MB・PDF）で出す
